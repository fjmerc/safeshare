Send a file

This page works with JavaScript turned off, for example in Tor Browser on its Safest setting.

How it works

  1. You choose a file, and can add a message.
  2. The server removes hidden information from the file, then locks the file and the message with the recipient's key, before storing anything.
  3. You get a code. Give it to the recipient the way you agreed. Only the person with the matching private key can open what you sent, not the server or anyone who later gets hold of it.

What the server can see. Your browser doesn't encrypt anything here, so the server handles your file unencrypted for the moment it takes to lock it. Someone who controls the server while you upload could read it. If you can use JavaScript you trust, or the safeshare-cli tool, those encrypt on your own device instead.

Send

Send a file, a message, or both. Large files may be refused; if yours is, you'll be told the limit.

Hidden information

Before locking it, the server removes:

  • JPEG and PNG photos: location, camera details, dates and other EXIF/XMP data.
  • PDF: author, title, dates, the software used, and the document IDs.
  • MP4, MOV and MP3: the metadata tags (location, dates, device, titles).
  • Word, Excel and PowerPoint (.docx, .xlsx, .pptx): the document properties (author, company, dates). Comments and tracked changes keep the names of whoever wrote them: remove them in Office before sending.

If that fails, nothing is sent. Other kinds of file are sent as they are. Nothing can remove what is visible in the file itself, such as a name in the text or a face in a photo.
